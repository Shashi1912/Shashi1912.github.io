# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page static portfolio site for Angajala Shashikumar (freelance QA / Software Test Engineer), themed around a bug→butterfly metamorphosis ("From Bugs to Brilliance"). No framework, no build step, no dependencies, no tests — plain HTML/CSS/JS served as files.

This folder lives inside the `D:\Automation_Engine` git repository (which has its own CLAUDE.md for the engine); commits from here land in that repo.

## Commands

```bash
python -m http.server 8000    # serve from this folder, open http://localhost:8000
npm install                   # once: dev-only test runner (Playwright); then `npx playwright install chromium`
node tests/make-resume-pdf.js  # rebuild assets/Shashikumar_Angajala_Resume.pdf from resume.html after config changes
npm test                      # 38 browser tests: plays every game, checks config-driven links, AI desk rules, theme, resume page
npx playwright test -g "chaos mode"   # one test by name
```

Opening `index.html` directly also works (relative paths, no fetches; the service worker and PWA install need http/https). There is no build or lint step. `.github/workflows/test.yml` runs the suite on every push. Tests use `tests/serve.js` on port 8791 and click orbs with `force` because the dock bobs.

## Content source of truth

- **`config/site-config.js`** (`window.SITE`) is what the site and `resume.html` actually render: links, About, stats, career timeline, projects (with optional `story` case studies), sample bug reports, and the resume page data. Edit content there, not in `index.html`. `{years}` in any config string is replaced by the `years` setting (expanded in place by `content.js` and `resume.js`). `config/README.md` is the plain-language guide for the site owner.
- `portfolio-data.json` / `PORTFOLIO.md` — the original collected profile data (2026-11-09) and collection notes. Keep them consistent with `config/site-config.js` when facts change.

## Page order (deliberate)

The page reads in two acts, and new sections should respect that split:

1. **The professional story** (what a recruiter or client needs in the first minute): hero with `heroFacts` chips and "See my work" / "Download resume" → expertise strip → About + the four stat counters → Projects → Experience timeline → "How I test" (investigations + sample bug reports) → Services.
2. **`#playground` band** ("Seen enough to talk?" resume/contact buttons on the left, jump links on the right), then the hands-on part: metamorphosis journey → QA Lab + Test bench games → AI desk → live scorecard.

Contact is always last. The nav mirrors the acts (About, Projects, Experience, How I test, Playground, theme toggle, Get a quote). First-screen calm is intentional: the games hint only appears after the visitor scrolls past the hero, the pointer trail runs only in the hero and playground sections, and the theme toggle lives in the nav rather than as a third floating orb.

## Architecture

Load order matters. CSS: `base.css` → `design.css` → `features.css`. Scripts (classic, sharing top-level `const`s as globals): `config/site-config.js` → `content.js` → `main.js` → `wingreveal.js` → `arcade.js` → `extras.js` → `ai.js` → `sound.js`.

**Effect switches** (`effects` in `config/site-config.js`, a missing switch counts as on; `false` must give exactly the behaviour from before that effect; reduced motion turns all three off): `wingReveal` (wingreveal.js), `wingFlap3D` (the 3D butterfly rig and the 2D canvas beat; `main.js` reads it through `FX`), `scrollStory` (the scroll story IIFE at the end of `main.js`; every story CSS rule hangs off `html.story`). Tests flip them with `page.route` on the config, using a regex anchored to the property line (the comments contain the same words).

- **`content.js`** renders About, stats, timeline, projects, bug reports from the config *before* `main.js` runs, so observers, h2 word-splitting and bug placement see final markup. All config text is escaped. Card art is a keyed SVG map (`art: 'chat'|'radar'|'gauge'|'vr'|'sheet'|'plane'`).
- **`main.js`** is the former inline script (intro, flock, journey, games registry, celebration, contact effects).
- **`arcade.js`** adds four Test-bench games (spot the defect, flaky test, log detective, defect interview) and Chaos mode via `addGame()`.
- **`extras.js`**: theme orb (`data-theme` on `<html>`, set before paint by an inline head script, stored as `sk-theme`), winner badge PNG, keyboard catch button, engine replay dialog (turn data copied from real run `20261022_113558`), live scorecard (Performance API), service-worker registration.
- **`ai.js`**: AI desk (Ask / Test cases / Bug report / Job fit). Uses the browser's on-device `LanguageModel` (Prompt API) when available, else rule engines in the same file; both are restricted to facts built from the config, and all output is rendered with `textContent`.
- **`wingreveal.js`** (after `main.js`; switch `effects.wingReveal` in the config, `false` = original straight scroll): every `main > section` after the hero and the `.midband` get two `.wr-panel` 3D wing panels in the colour of the element above (recomputed on theme change), hinged at the screen edges and clipped to a swallowtail-shaped opening that widens with scroll (fully open by ~52% of the viewport), beating with scroll speed, plus a `.wr-hinge` butterfly body. Never intercepts scroll; `pointer-events:none`; large jumps (nav anchors) snap open; focus inside a section opens it at once; off under reduced motion and in print. Note the scripts order is now `… main.js → wingreveal.js → arcade.js …`.
- **`resume.html` + `resume.js` + `resume.css`**: print-ready resume built from the same config.
- **`sw.js` + `manifest.webmanifest`**: network-first offline cache; bump `CACHE` and the `FILES` list when files are added.

The three original layers:

1. **`base.css`** (formerly the inline `<style>` block) contains *layered* themes: a base light theme, then a dark-grove theme appended below it that overrides the base (same selectors, later wins). Then `design.css`, then `features.css` (new features and the night-grove dark theme at its bottom).
2. **`design.css`** ("Forest editorial") overrides the inline styles again, and its *bottom* section ("Realistic assets override…") overrides its own earlier rules to size the photographic butterfly/caterpillar. CSS is cascade-by-append: new restyles are added at the end rather than editing earlier layers. Keep that pattern (or be prepared to untangle all layers at once).
3. **`sound.js`** — WebAudio-only ambient score (synthesized chords plus periodic wing-beat puffs of band-passed noise, deliberately no audio files or streaming). Listens for the custom `metamorphosis` window event to play phase stingers.

Page behavior in `main.js`:

- **Butterfly/caterpillar instances**: `<template id="butterfly-shape">` holds a hand-drawn SVG emerald swallowtail, *Papilio palinurus* style (viewBox `0 0 540 460`: velvet-dark scalloped wings with tails, an emerald band with a blurred glow duplicate under it, feTurbulence scale-shimmer, lunules, veins; `.wing-left`/`.wing-right` groups, each split into `.hind` and `.fore`, plus a `.bf-bodyg` body group). `butterfly(host, prefix, tpl?)` clones a template and remaps element IDs plus `url(#…)` references in **both `fill` and `filter` attributes** per instance; with `effects.wingFlap3D` on (and motion allowed) it then builds a 3D rig for the butterfly template (off: the original single SVG, flapped flat by `scaleX` on `.wing-left`/`.wing-right` around `270px 238px`): `span.morpho.bfly > span.bf-rig >` five stacked `<svg class="bf-layer">` on the same viewBox (left hind, right hind, left fore, right fore, body with the `<defs>`; gradients are referenced across layers). Each wing layer turns on the body hinge with `perspective(170cqw) rotateY()` (`.bfly` is an inline-size container, so every size looks alike), the forewing leads and the hindwing lags 5% (the fold bends the wing), with a short clap above the body, a slow upstroke and a fast downstroke (keyframe easings), brightness tied to the angle and a lift of the rig on the downstroke (`bfForeL/R`, `bfHindL/R`, `bfLift` at the end of `features.css`). Speed per host comes from `--flap` (hero 3.6s default, intro 2.6s, journey 2.2s, logo 3s, guide 1.15s, drifters .95s); `.done`/`.paused`/`.idle` pause it, reduced motion leaves the wings flat and open. The caterpillar template is cloned unchanged. Canvas butterflies (`#flight`, `#swarm`, `#brandfly`) share `flapOpen(p)`/`flyPath()` at the top of `main.js` when `wingFlap3D` is on: the same asymmetric beat in 2D, with lagging curved wing tips (off: their original `|sin|` flap drawing);  hosts: hero `.bloom`, intro `#introShape`, journey `.emerged`, scroll-following `.guide`, the nav logo `.mark` next to "Shashi", and three ambient `.drift` butterflies in the hero (`.d1/.d2/.d3`, sized and `hue-rotate`d per class), which are flown by a JS steering loop (`flyLoop`: wander noise, banking into turns, horizontal wrap; their old CSS flight keyframes are overridden with `animation:none`). The hero also has pointer+scroll parallax (`--bgx/--bgy` on `.hero` background-position, plus different translate rates for `.bloom`, `.wrap`, and the `#flight` canvas). Section `h2`s are split into word spans for staggered rise-on-reveal — the class is `wsplit`, NOT `split`, because `.split` is the site's two-column grid layout class and blockifies the spans. `<template id="caterpillar-shape">` is an SVG caterpillar with `.seg` body-wave and `.leg` walk-cycle animations (per-element `animation-delay` inline), cloned into journey `.larva` and QA-lab `.bug`. The right wing is mirrored by an *attribute* transform on an outer `<g>` so the CSS animation on the inner group doesn't overwrite it — keep that nesting. `assets/morpho-real.png` / `caterpillar-real.png` are the retired photo versions, no longer referenced.
- **`#flight` canvas**: a ~2400-particle butterfly flock. The same canvas element is physically moved (`prepend`) between the `#intro` overlay (dense swarm during the opening) and the hero (sparse ambient flock after). `startScene`/`finishScene` also manage `inert` on main/header/footer and focus.
- **Journey section**: 3-phase metamorphosis driven by `data-phase` on `.habitat`, auto-advanced on a timer gated by IntersectionObserver visibility, pause button, and tab visibility; each change dispatches the `metamorphosis` event (consumed by sound.js).
- **Career + Projects sections** (`#milestones`, `#projects`): real profile content from `portfolio-data.json`. A generic scroll-reveal system (`[data-reveal]` + IntersectionObserver adds `.seen`, stagger via `--d` inline delay) drives the timeline vine (`scaleY` on `.timeline:before`), node reveals, and project cards; stat numbers count up once via a second observer reading `data-n`/`data-s`. `#projects` leads with a featured dark card for the Automation Engine whose fake console animates the six turn-loop steps (`.console li` staggered by `--i`); each grid card has an inline-SVG illustration with its own idle animation (`.sweep`, `.needle`, `.lens`, `.row`, `.dot`, and `.plane` on an `offset-path`).
- **Living wordmark**: the nav brand is `#brandfly`, a canvas where ~300 tiny butterflies fly in from scattered positions and assemble "SHASHI" left-to-right (offscreen-canvas text sampling at a 3px grid, grove-palette colours per theme); once formed, the swarm cross-fades into crisp Georgia text drawn on the same canvas and the rAF loop sleeps until hover, a theme flip or an intro replay wakes it. The formation clock is held while the `#intro` overlay lacks `.done`, so the assembly plays after the intro ends and replays with the intro. Hovering scatters the swarm; leaving re-forms it. Under reduced motion the canvas hides and the plain `.brandtext` span shows; the real name lives in the `<strong>`'s aria-label. Note: rAF freezes while the Browser pane is occluded, so verify this animation with the pane visible.
- **Nav**: the section links sit in `#navMenu.navlinks` (`display:contents` on desktop). Under 900px they fold into a panel under the header opened by `#navToggle` (aria-expanded; Escape, a link click, an outside click or focus leaving closes it; code at the end of `extras.js`). `nav .btn` and the theme toggle stay in the bar.
- **Offscreen pause**: `extras.js` marks sections outside the viewport (+200px) `.idle`, which pauses their CSS animations (not the `.console`); JS timers, canvases and dialogs are unaffected. Hero drifters steer around a keep-out box over the hero label, headline and intro line (`keepRect` in `main.js`).
- **Scroll story** (switch `effects.scrollStory`; IIFE at the end of `main.js` + the "Scroll storytelling" block in `features.css`): `html.story` is set only when the switch is on and motion is allowed; off, nothing is built (no `.tone`, no `.pin` wrapper, no guide stages). One passive scroll listener schedules one rAF that reads `scrollY` only (geometry is cached by `measure()` on resize, load and a `ResizeObserver` on `main`) and writes opacity/scale/custom properties: the `.guide` companion cross-fades caterpillar → cocoon (around `#playground`) → butterfly (from `#contact`), eased so it trails the scroll; the career vine is `scaleY(var(--vine))` with `.node.lit` as the tip passes; two fixed `.tone` layers cross-fade the paper/sage tones behind the (transparent) light sections, while `#work`, `.midband` and `footer` get soft gradient edges. Native CSS scroll-driven animations (`@supports (animation-timeline: view())`) add parallax (headline, eyebrow, media) and, at ≥1000px, a pinned horizontal slide of `.projgrid` inside `.pin > .pin-stage` (wrapper added by the script; card DOM order unchanged; focusing a card scrolls to where the slide shows it). Native scrolling is never intercepted. In print the story steps aside (no tone layers, normal project grid). Independent of the switches: the career heading sticks as one `.mile-head` block on desktop, sections and the progress bar clip horizontal overflow (`overflow-x:clip`; perching `.pfly` and 3D wings can never widen the page), and the nav logo butterfly hides at ≤360px.
- **Wing reveal × scroll story**: with both on, the light sections are transparent over the `.tone` layers, so `bgOf()` would read the wrong colour. The story tick paints the wing panels of every boundary below a light section with the tone colour actually on screen (the sRGB mix of tone A and B, inline `--wr-prev` on the panels), and the soft gradient above `#work` is dropped because the wing reveal takes that boundary. Wing panels never extend over the pinned `.pin` slide and stop easing once it is on screen. `wingreveal.js` reads every section rect first and only then writes. With the slide on, the bug-hunt spot in project cards is limited to the first three cards.

- **Explorer features**: a scroll-progress bar in the header (`.pageprog`) with a caterpillar `.walker` that becomes a butterfly past 98%.
- **Field games + floating dock**: sound and games are two bobbing glass orbs, bottom-left `.sound-panel` (♫ icon → animated `.eq` bars when on; volume slides out on hover/focus) and bottom-right `.quest` (`#questOrb` with an SVG progress ring, badge, and a `#questPanel` listing each game). Both hide while the intro runs (`#intro:not(.done)~…`), so their markup must stay a later body-level sibling of `#intro`, and `.quest` must exist before the main script runs. Games register through `addGame(id,{name,desc,total,tips,win,href,icon,motion})`, which also builds the panel row; call `score(id)` to advance one. Progress is NOT saved: every load, refresh or new browser starts all games at zero (the owner asked for this). On load `store.clear()` also removes `sk-games` left by older versions; only `sk-theme` is kept. `#questReset` restarts the games in place by reloading. Games: **bug hunt** (five `.hidebug` buttons created by the script at random spots each visit: one from `bugClosed` inside a closed investigation `<details>`, four from `bugOpen` in distinct sections; the hero spot also randomizes its position; the markup holds no static bugs), **butterfly catch** (click the hero `.drift` flyers; a caught one flees off-screen via `flee` in `flyLoop` and returns; dropped from the totals under reduced motion because the drifters are hidden), **defect lab** (a failing run on the original build, then a passing patched-build run that includes 0, hooked in `execute()`). Progress shows a `#questTip` bubble; finishing a game opens the `#celebrate` card (emerging butterfly) over a `#swarm` canvas burst, with a bigger gold "grand" version when every game is done (plus a `#celBadge` PNG download). "Keep exploring" scrolls to the resume card. The dock pauses its bob while hovered or open. Events `gameprogress` / `gamecomplete {all}` drive sound.js chimes and fanfare.
- **Contact highlights**: resume and email are `.flycta` cards (shimmering gradient border, a flapping SVG butterfly, three `.pfly` micro butterflies that perch on scroll-in via `.reach.seen`, scatter on hover, and a dust stream while hovered); footer Email/Resume links are `.flylink` with a micro butterfly.
- **QA Lab**: the boundary-value demo's "Original build" intentionally accepts 0 (off-by-one defect) while "Patched build" doesn't — `check()` encodes this; it's the point of the section, not a bug to fix.
- **`config/site-config.js`** (loaded just before the main script; a plain script, not JSON, so it also works from `file://`): `window.SITE = {email, linkedin, github, resume}`. The script rewrites every `[data-cfg="email|linkedin|github|resume"]` href, every `[data-cfg-text]` text and every `[data-repo]` link (`github + '/' + repo`); the hrefs written in the markup are only fallbacks. New profile links should carry one of these attributes instead of a hard-coded URL.
- **Contact form**: `contactEmail` comes from `SITE.email`; an empty email makes the form download a `.txt` brief instead of opening mailto. Nothing is ever sent to a server.

## Conventions that must survive edits

- Fully static and offline: no CDNs, no external fonts, no network requests, no audio downloads, no cookies (the scorecard and a test assert zero third-party calls). Assets are local files in `assets/`. `node_modules` is dev-only and git-ignored.
- Never fabricate profile facts: testimonials, metrics and employers come only from the user. The AI desk must answer only from config facts.
- Every animation respects `prefers-reduced-motion` (intro, guide, flock, journey, sound panel are disabled or skipped). Any new animation needs the same guard.
- Accessibility patterns in place: skip links, `aria-live` outputs, `aria-pressed` toggles, `inert` during the intro overlay, focus-visible outlines. Keep them when touching those areas.
